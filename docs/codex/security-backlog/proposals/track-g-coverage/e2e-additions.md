# Prioritized E2E additions — final acceptance for `fill-in-mocked-data`

This is planning only; no tests are implemented here. Row IDs (R1.3, S1.5, ...) point to `coverage-matrix.md`.

## Ground rules for the list

- **Read-only (RO) first.** RO specs need no Admin credential, no lease, and no cleanup, so they can run today while stateful execution is blocked (no Admin key, and live rules deny the clinician's own `practitioners/{uid}` read). Several checks below are currently locked inside stateful specs even though they only read. Moving or copying them to RO unblocks acceptance evidence.
- "RO" means the same thing as the existing `patient.readonly` spec: login, navigation, opening and cancelling dialogs, reads, and downloads are fine. Anything that saves a form is stateful. The one existing caveat still applies: the app may back-fill missing profile fields when it loads.
- **Stateful (SF) additions** must go through the `stateful` fixture, a lease, plan-then-execute cleanup, and Admin persistence assertions. Every created document needs **positive run evidence**: the run marker in a field the test writes, plus owner fields and a server time inside the run window. Every modified fixture document needs a `restorableFields` entry that lists exactly the fields the code path writes.
- Complexity: S = under half a day on existing helpers; M = new helper or probe; L = new cleanup attribution rules plus harness unit tests in `e2e/harness/cleanupPlan.test.ts`.

## Not recommended for E2E

- `deviceAssignments` and `protocolCatalog`: no UI path calls them (`storageEngine.saveDeviceAssignment` has no component caller; `protocolCatalog.ts` is in-memory only). Rules-emulator coverage is sufficient. Add attribution rules only when a UI ships.
- Protocol runtime math (T1.1/T1.2), badge rules, and analytics adherence: unit coverage is the right layer.
- Muse BLE, BrainFlow live board, disconnect/stall/recovery, signal quality, headset fit, real QEEG file import, and live telemetry are **manual/hardware only**. Demo Mode does not cover them.
- Two-tab appointment revision conflict and offline message send: optional, low value versus the existing unit tests.
