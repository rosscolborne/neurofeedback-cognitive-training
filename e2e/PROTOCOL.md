# Local protocol and reward Playwright coverage

Run `npm run test:e2e:protocol` from the repository root. The command starts local Firebase Auth and Firestore emulators, Vite on port 5193, and the isolated protocol, messaging, and persistence browser suites. Java 21 is required for Firestore; set `PATH` to include a local JRE when necessary.

The suite uses the `demo-neurasticity-protocol-e2e` project ID, creates fresh clinician and patient accounts in the emulators, and signs in through the normal UI. It never uses `.env.e2e`, stored authentication states, shared Firebase accounts, or deployed rules. The browser Firebase setup and fixture helper both reject other project IDs or missing emulator settings. Data disappears when the emulators stop.

The protocol suite covers assignment, reload, patient details, Demo training, telemetry, and malformed persisted rules. The messaging suite verifies bidirectional UI delivery, reload persistence, and denial of an unrelated identity against the same local rules. The persistence suite verifies that its assertions read sessions, appointments, messages, invitation and profile state, clinic branding, and user roles as the patient or clinician; an outsider is denied those paths. The cache-isolation persistence spec signs accounts in and out of the same browser profile (including a second tab, an account switch and a deletion that is held up) and checks that the next account cannot read the previous account's cached Firestore data, while the same account keeps its offline data across a reload. The back-forward-cache persistence spec runs Chrome with its back/forward cache enabled and checks that Back after an account deletion or a sign-out shows none of that account. Exact spectral calculations, frequency boundaries, and rolling percentage math remain in Vitest. Headset acquisition and signal quality require manual hardware testing.
