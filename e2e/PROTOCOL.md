# Local emulator Playwright coverage

Run `npm run test:e2e:protocol` from the repository root, after `npm ci --prefix functions`. The command builds `functions/lib`, starts local Firebase Auth, Firestore and Functions emulators (trusted scoring writes each game session's `result` and progress, NFCT-22), Vite on port 5193, and the isolated protocol and persistence browser suites. Java 21 is required for Firestore; set `PATH` to include a local JRE when necessary.

The suite uses the `demo-neurasticity-protocol-e2e` project ID, creates fresh accounts in the emulators, and signs in through the normal UI. Patients are seeded with the Admin SDK on the current account model (a `users/{uid}` role and a `clients/{uid}` profile) and have no clinician relationship; the clinician product is retired, and a practitioner account that signs in sees only that it is unsupported. It never uses `.env.e2e`, stored authentication states, shared Firebase accounts, or deployed rules. The browser Firebase setup and fixture helper both reject other project IDs or missing emulator settings. Data disappears when the emulators stop.

The protocol suite (`protocol.local.spec.ts`) checks the consumer EEG boundary: a fresh consumer sees no EEG protocol, reward, calibration or neurofeedback training on Home, Train, Progress or Profile, and headset setup is pairing and fit only. The persistence suite verifies that its assertions read the user role as the patient; an outsider is denied the patient's profile and user role. The cache-isolation persistence spec signs accounts in and out of the same browser profile (including a second tab, an account switch and a deletion that is held up) and checks that the next account cannot read the previous account's cached Firestore data, while the same account keeps its offline data across a reload. The back-forward-cache persistence spec runs Chrome with its back/forward cache enabled and checks that Back after an account deletion or a sign-out shows none of that account. The Mental Math lifecycle suite (`mental-math.lifecycle.local.spec.ts`) plays the game through the signed-in UI with Playwright's `page.clock`, so a 90-second run takes no real 90 seconds; the Vite server it runs against gives every game session the same fixed seed, which exists only when `VITE_E2E_EMULATORS` is set on a dev server for this project (`src/consumer/repositories/e2eSessionSeed.ts`). The Train catalogue spec (`train-catalogue.self-directed.local.spec.ts`) signs up through the UI and checks that the Train tab lists only the code-owned games, each with its domains, and that a game opens and Back returns to Train; it also runs in WebKit at iPhone sizes. The Home and Progress spec (`home-progress.lifecycle.local.spec.ts`) plays a first run from Home's Play and checks, once trusted scoring has written the stats, the one-day streak, this week's training day, and the first-run achievement on Home and Progress, with no neurofeedback training or history; it also runs in WebKit at iPhone sizes. The EEG pipeline's fit, hosted-analysis and score handling are covered in Vitest. Headset acquisition and signal quality require manual hardware testing.
